HDRI vs LDR Environment Maps: Lighting, Formats and Tone Mapping

Two environment maps can look similar in a preview and produce very different lighting. Projection tells you where each pixel points; dynamic range tells you how much light that pixel can represent.

By 360 Panorama Viewer · Updated 19 October 2026 · 4 minute read

HDRI and LDR describe pixel values, not projection

An environment map records the surrounding scene in all directions. It can be stored as one equirectangular image or six cube faces. Either layout can hold high or low dynamic range pixels. Calling a file a cubemap, skybox or 2:1 panorama does not tell you which range it contains.

A conventional 8-bit JPEG is a display image. Its highlights have already been fitted into a limited output range. A scene-linear HDR environment can represent a bright window or sun many times brighter than nearby surfaces. A renderer can use those relative values for image-based lighting and reflections.

Why range matters for lighting

Consider a room where a wall has a linear value of 0.5 and a bright window reaches 50. The ratio is 100:1, or about 6.6 stops. If both are compressed into a display image, their relationship changes. The window may look white in both versions, but its contribution to a rendered scene can be much weaker in the display version.

Increasing the strength of an LDR environment scales every pixel. It can brighten a render, but it cannot reconstruct the original ratio between a clipped light and its surroundings. An LDR environment can still provide useful ambient color and a visible backdrop; additional scene lights may be needed to achieve the intended illumination.

Radiance RGBE packs red, green and blue mantissas with one exponent per pixel. OpenEXR supports several channel types and can carry additional channels or layers. Read the OpenEXR technical introduction for its storage capabilities. The filename extension identifies a container, not how the image was captured or processed.

A .hdr export cannot recover lost light. Saving an 8-bit image in an RGBE container does not restore clipped highlights. This site's current AI HDRI export wraps generated 8-bit panorama pixels in Radiance format; it does not measure or reconstruct the original scene's radiance.

How to inspect an environment map

  1. Open a Radiance file in the HDRI viewer. It decodes source RGBE values into floating-point pixels.
  2. Lower exposure to inspect bright areas, then raise it to inspect shadows. One EV doubles or halves the linear values before the display curve.
  3. Look for detail that a display preview might conceal. This is a visual check, not a calibration measurement: normalization and previous processing affect absolute values.
  4. Check coverage and seams. A correct dynamic range does not repair a missing nadir, misaligned horizon or mismatched image edges.

The viewer applies an ACES-style filmic approximation followed by sRGB encoding. It is a display preview, not a full color-managed match to every renderer. OpenEXR decoding is not supported by this tool; use a compatible desktop application for EXR sources.

Tone mapping changes what you export

Tone mapping compresses scene values into a range suitable for display. An exposure control selects a brighter or darker view of the source before that compression. A downloadable PNG records the resulting appearance; its 8-bit pixels no longer retain the original radiance values.

The HDRI viewer's six-face ZIP is also made from that tone-mapped image. Those PNG faces can provide a visible skybox, but they are not floating-point HDR cube faces. Keep the original .hdr when a renderer needs environment lighting. Changing a PNG filename to .hdr does not convert its pixels or restore range.

Where to get a suitable source

For a real captured location, a bracketed HDR capture workflow combines different exposures before tone mapping. Keep exposure brackets aligned, manage movement between frames, and preserve the scene-linear result. For a virtual environment, render scene-linear HDR from the 3D scene. Neither workflow requires a display export to become the lighting master.

The AI HDRI generator is useful for exploring environment concepts and exporting a Radiance-compatible backdrop. Evaluate the actual source range and the result in your renderer before using it for lighting. A generated sky's visual appearance alone cannot establish physically accurate illumination.

Choose an export for the job

  • Sharing a panorama: use a display image and appropriate metadata.
  • Building a visible skybox: use a supported panorama or cube-face layout and verify orientation.
  • Lighting a scene: retain the original scene-linear HDR environment and configure the renderer's color interpretation correctly.
  • Reviewing a file: use an exposure-controlled preview, then compare with a test render.
