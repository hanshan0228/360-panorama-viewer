Facebook 360 Photo Not Working? 7 Checks for a Flat Upload

A flat upload can come from missing metadata, the wrong projection, or the publishing app. Check the source file first so you know which part of the workflow needs fixing.

By 360 Panorama Viewer · Updated 31 October 2026 · 4 minute read

First, check that the file actually contains a sphere

Open your image in the free 360 panorama viewer. Look left, right, up and down. A full photo sphere includes the scene behind the camera, the sky overhead and the ground below. If the image is a narrow phone panorama, an ordinary photograph or a screenshot, changing its metadata cannot create the missing views.

For a complete equirectangular panorama, use the conventional 2:1 canvas, such as 4096 × 2048. The ratio alone does not prove that the projection is correct. A normal photo stretched to 2:1 still has the wrong geometry. Partial panoramas can use crop metadata to describe their position inside a larger sphere; they do not have to be 2:1 themselves.

Seven checks before you upload again

  1. Check the projection. Use the equirectangular export from your camera or stitcher, rather than a fisheye frame, cube-face strip or flat screenshot. A screenshot of a 360 viewer records only the direction you were looking.
  2. Check the panorama dimensions. For an uncropped full sphere, the image dimensions and full-panorama dimensions should agree. If you resized the file, stale dimension tags can describe a different image.
  3. Check for GPano XMP metadata. This describes the projection and crop. Editors and image optimizers may omit it on export. Search for the GPano namespace with a metadata inspector; a plain-text search can provide a quick clue but is not a complete validation.
  4. Use the downloaded JPEG. Our metadata tool exports a JPEG with a Photo Sphere XMP packet. Upload that file directly. PNG and WebP inputs are converted to JPEG; that conversion can change pixels.
  5. Avoid an intermediate image copy. A messaging app, screenshot or publishing service may recompress the image or strip its metadata. Compare the file immediately before uploading with the original tagged download.
  6. Try a different upload client. If a valid file works in a dedicated viewer but is still flat on Facebook, try the desktop uploader or another current client. Recognition can vary by upload surface and account; correct tags do not guarantee platform support.
  7. Check the resulting post. Allow processing to finish and reopen it. If you reduce resolution or otherwise re-export the image to troubleshoot an upload, inspect or repair metadata again afterward.

What the GPano dimensions mean

These values follow Google's Photo Sphere XMP specification. For an uncropped 4096 × 2048 full sphere, the key values are:

GPano fieldExample value
ProjectionTypeequirectangular
FullPanoWidthPixels4096
FullPanoHeightPixels2048
CroppedAreaImageWidthPixels4096
CroppedAreaImageHeightPixels2048
CroppedAreaLeftPixels0
CroppedAreaTopPixels0

UsePanoramaViewer=True requests spherical viewing, but the receiving application decides how to display the file. Initial-view heading and pitch describe a starting direction; support for those optional controls varies between viewers.

Do not fix a partial panorama by pretending it is complete. Cropping or stretching a phone panorama to 2:1 does not add sky, ground or a missing reverse view. Use a stitcher that preserves partial-sphere crop information, capture a full sphere, or generate the missing scene.

Inspect the file you actually upload

If you have ExifTool installed, run this read-only command on both your original and final JPEG. Replace the filename with the path to each file:

exiftool -a -G1 -s -ImageWidth -ImageHeight -XMP-GPano:all "final-panorama.jpg"

Compare the image dimensions with CroppedAreaImageWidthPixels and CroppedAreaImageHeightPixels. For a full, uncropped sphere, the full dimensions should match too, and the crop offsets should be zero. Missing GPano output is a clue that this file has no readable GPano tags; it does not establish why Facebook displayed it flat. See the ExifTool FAQ for the duplicate-tag and group options.

Metadata can also include location and camera details. Inspect what you intend to share before publishing; adding panorama tags does not itself remove existing location data.

Repair metadata in the browser

  1. Finish editing the full equirectangular image.
  2. Open the 360 metadata injector and choose that final file.
  3. Select Inject & Download 360 JPEG.
  4. Upload the downloaded JPEG directly, without passing it through another editor.

JPEG inputs keep their original encoded image data while the panorama packet is added. PNG and WebP inputs are encoded as JPEG first. Processing runs locally in your browser. Keep an original copy so you can compare results.

When metadata is not the answer

A seam, tilted horizon or blurry sky is a pixel problem. Metadata identifies how to display the scene; it does not repair the scene itself. Use the projection guide to check the geometry. If the social upload path still displays a valid file flat, test another supported sharing method separately; a local viewer check does not confirm that Facebook will recognize the upload.

This guide concerns still photos. A panning clip exported by the 360 photo to video tool is a conventional video view of the scene; JPEG tags cannot make a video spherical.
