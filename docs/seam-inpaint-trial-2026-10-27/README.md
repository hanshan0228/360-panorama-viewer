# 接缝局部重绘实测（2026-10-27）

本地实验，未修改或部署网站生成流程，也未操作网站用户账本。一次 Gemini 文字生图及两种 GPT Image 局部编辑输入方案用于验证可行性。实际推理通过本机已配置代理执行；没有把密钥写入实验文件。

## 为什么首页海滩和新生成图不同

已核对线上 `https://360panoramaviewer.com`：首屏资源是固定的 `coastal-cover` 图片（2560×1280），不会每次实时生成。线上公开模型配置显示 failover 的 primary 为 `gemini-flash-img`（`gemini-3.1-flash-image`），secondary 为 `gemini-imagen3`（名称虽旧，实际模型为 `gpt-image-2.5`）。因此不能从“默认模型”标签推断每次实际调用哪一个模型。

用户补充确认：首页海滩也是此前用这套工具生成的。“固定资源”仅解释展示方式，不能解释其画质优于新图，不能据此推断它来自其他工具或制作流程。当时的确切模型、提示词及生成参数尚未找回。

线上当前 bundle 确实使用 `preserveNative: true, sharpness: 0, contrastBoost: 1`，不能把当前画质问题直接归因于前端默认放大或锐化。原生像素不足、模型画出的纹理/投影问题和接缝后处理须分别检查。

进一步实测这张 2560×1280 海滩资源：左右边缘平均色差仅 1.8266，相邻列基线为 7.0646；当前自动修缝直接跳过，改变的 RGBA 通道值数量为 0。它作为现存成功结果，本来已经有较好的边界颜色连续性，不需要靠当前融合算法掩盖较大断层。这只验证颜色连续性，不等于完整球面几何验收，也不证明它当初从未做过修缝。

Git 记录显示该文件在 `999d373`（2026-10-17）加入仓库；该版本 `GeneratorTab.tsx` 的修缝初始状态是 `useState(false)`，当前为 `useState<boolean | 'auto'>('auto')`。这是可核实的行为差异，需要在实际失败图上做关闭/开启对照；入库时间不代表生成时间，也不能据此证明当初用户实际采用了关闭状态。

本次没有拿到用户具体失败图，因此结果只适用于这张新生成测试图及本机代理当前行为。

## 测试输入与第一轮

- 用网站当前主通道 Gemini Flash 生成新的夕阳海滩，2K 请求，返回 JPEG 2752×1536，耗时约 21 秒。完整提示词见 `generation.json`。
- 按当前准备流程裁剪为 2752×1376，不放大、不锐化。
- 自动修缝检测：边缘色差 24.12，相邻基线 11.84，不超过三倍阈值，直接跳过修缝。`gemini-repair/old-blending.png` 与 `original.png` 在本例相同；因此本例不能证明自动融合造成了原图模糊，也不能作为其严重涂抹的真实复现。
- 水平平移半张图，将接缝移到中央，提供宽 430 像素的透明蒙版给 GPT Image 2.5。
- 要求输出 2752×1376，上游实际返回 1774×887。仅重绘带被缩放回原坐标；带外原图逐像素保持。编辑耗时约 60 秒。
- 首版合成发现模型响应的透明通道会带入结果，已修正为在原图不透明背景上合成；使用保存的同一响应复算，没有额外模型请求。初始阶段记录见 `initial-composite-result.json`，最终记录见 `result.json`。
- 修正透明通道后，边缘色差降到 9.77，修复带外改变像素数为 0，非不透明像素数为 0。但视觉上修复区更软，树干出现移位与羽化重影。**第一轮不通过画质验收，不可称为解决。**

## 第二轮：只上传接缝附近的原生裁块

用同一张原图，将模型输入从整张全景缩为中央 1024×1376 裁块，保留完整高度与接缝两侧上下文。蒙版仍映射到同一全景位置；模型返回的裁块仅合成到原图修复带，其余区域保持原字节。

第二轮返回 1082×1454，耗时约 50 秒，局部像素密度比整图输入更好。合成后仅 428 列有变化，修复带外改变像素数为 0，非不透明像素数为 0；边缘色差由 24.12 降到 10.13。

实际对照图中，局部细节较第一轮改善，但树干位置变化、修复带边缘的重影仍可见。**第二轮也不通过画质验收。不能据此把 GPT 重绘方案接入自动生图。** 原始响应、对照图及像素统计保存在 `gemini-crop-repair/`。

后续应优先验证能真正约束蒙版内采样、保留边界上下文的 inpainting 工作流，或全景专用模型；继续加提示词、放大输出或扩大融合带没有充分证据能解决本次结构漂移。当前代理的商业 API 能力、其他模型及用户实际失败图尚未完成实测。

## 复现

依赖项目现有 TypeScript、本机已安装 Playwright 和独立无头 Chrome；不安装新依赖。

```sh
node --test tests/seam_inpaint.test.mjs tests/panorama_processing.test.mjs
node scripts/try-seam-inpaint.mjs \
  --input docs/seam-inpaint-trial-2026-10-27/gemini-original.jpg \
  --output /tmp/panorama-seam-trial \
  --crop-width 1024 \
  --proxy-config '/Users/han/Library/Application Support/CLIProxyAPI/service/config.yaml'
```

也可用 `PANORAMA_EDIT_API_KEY` 与 `--base-url` 指定自己的兼容接口。`--prepare-only` 只准备输入和蒙版，不调用模型；`--edited 已保存响应.png` 重做合成与对照，不再调用模型。`PANORAMA_CHROME_EXECUTABLE` 可指定浏览器路径。

## 已验证与边界

47 项针对像素处理及原有流程的测试通过；lint 与 build 通过。像素工具验证了奇偶图宽的平移/逆平移、透明蒙版方向、羽化端点和修复带外所有 RGBA 字节保持。它们不替代画质验收。

GPT/代理可以忽略精确尺寸及局部编辑约束，HTTP 成功不等于真正在潜空间约束了局部区域。上游还有类似的[蒙版不生效报告](https://github.com/router-for-me/CLIProxyAPI/issues/5268)。本地强制回贴能保护带外像素，但无法保证模型重画的树干恰好对齐，也不能补救全局投影错误。
