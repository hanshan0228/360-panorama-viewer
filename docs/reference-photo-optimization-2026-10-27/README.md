# 参考照片转全景优化：2026-10-27

针对用户提供的 `cartarmor-hero-lifestyle-v2-1536.webp`。上一轮真实模型结果虽然保留了球车，却产生上方重复球场横带，以及右下角不存在的驾驶舱/方向盘；原模型图已经带有这些错误。

## 本地实现

复用 `buildPanoramaPrompt`，新增可选的参考图标记。在有参考图时，明确输入是同一场景某个方向的透视照片，要求在原观察位置生成单一、连续的 360×180 度球面环境；保留可辨识主体和材质，连续补全未拍到的区域。加入单一地平线、天空/天花板与地面/地板的上下方向、首尾同一背面方向，以及禁止上下拼条、拼贴、重复主体和凭空添加前景驾驶舱等约束。用户描述与选定风格仍进入请求；空描述不再生成空的“修改要求”标签。

`GeneratorTab` 直接调用这个共享构建器，代替单独拼接一段较弱的参考风格描述。文本模式输出保持原有行为。模型路由、调用次数、积分和修缝算法没有因本次改动而增加。未提交或部署。

全部使用同一张 WebP 参考图，通过已配置本机代理提交 Gemini 3.1 Flash Image，原生请求 16:9/4K；无模型回退、无网站登录或账本操作。无法独立核实代理背后的模型权重版本。

## 画质与几何限制

每个目录保留 `request.json`、`result.json`、原始模型 JPEG、2:1 处理后缩略图及六方向立方体检查图。production-prompt 另保存完整 `panorama.png`。处理复用网站现有 native-detail 中心裁切和 Auto 接缝融合，不放大、不锐化。

六面检查未发现此前的分屏横带；仍有顶部极点汇聚/拉伸、房屋与原图不同的补全，以及背面植被/光照接续瑕疵。最终原图首尾平均 RGB 色差 21.7867，Auto 后为 0；这仅证明边缘颜色被融合，不证明语义几何无缝。本次实现改善已复现问题，**不构成完全真实、无缝360场景的保证**。
